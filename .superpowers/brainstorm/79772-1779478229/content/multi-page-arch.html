Updated Architecture: Multi-Page App

Separate HTML files, shared CSS/JS, standard navigation

Page Structure

4 Separate HTML Pages
index.html → Focus Timer (Home)
script: timer.ts | circular progress, countdown, controls
settings.html → Settings
script: settings.ts | sliders, toggles, theme, sound picker
insights.html → Focus Insights
script: insights.ts | charts, streaks, achievements
garden.html → My Garden
script: garden.ts | plant gallery, growth stages, collection

Shared Assets (each page imports these)

styles/
• main.css (Tailwind build output)
• components.css (shared components)
• animations.css (organic transitions)
scripts/
• storage.ts (IndexedDB wrapper)
• state.ts (shared state/pub-sub)
• audio.ts (sound manager)
• components/ (shared TS components)

Navigation

Standard <a href="..."> links between pages. Each page includes the SideNav (desktop) and MobileNav, with the active page highlighted. No JavaScript router needed — simpler and more reliable.

PWA Notes

Multi-page PWA is fully supported. The service worker caches all 4 HTML files + assets for offline use. Each page has its own entry in the navigation, and the install prompt works across all pages.

This simpler architecture eliminates the need for a router and fits your multi-page preference. Does this look right?
